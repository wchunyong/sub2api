# API 密钥快速导入方案

日期：2026-09-05  
状态：首轮实现已提交到 `feature/quick-import-agents`，未合并或上线；真实网关及 macOS/Linux 实机验收尚未完成。验证记录见同目录上级 `plans/2026-09-05-quick-import.md`。

## 1. 目标与范围

降低新手用户创建 API 密钥后的配置成本，将 API 密钥列表操作列中的“使用密钥”“导入到 CCS”合并为“快速导入”。用户先选择 Agent，再选择该 Agent 对应的一键导入、CC Switch 导入或手动配置；一键清理也限定到已选 Agent。

首期自动脚本目标覆盖 Windows、macOS、Linux 下的 Claude Code、Codex 和 OpenCode。其他客户端保留现有手动配置及 CCS 导入能力，后续再接入自动脚本。可用能力必须结合已选 Agent、密钥分组、路由能力和操作系统判断，不生成无法使用的配置组合。

用户提出的 ChatGPT 作为独立产品意图保留，实施前需明确其具体目标是 ChatGPT 网页/桌面端还是 Codex。此项只影响 ChatGPT 卡片的适配，不阻塞其他 Agent 的方案。未确认具体目标及配置能力前，不把 ChatGPT 自动映射为 Codex，不生成 ChatGPT 导入或清理命令；Codex 使用独立名称。

CCS 在本文中特指 CC Switch。

## 2. 页面入口与交互

### 2.1 API 密钥列表

- 删除独立的“使用密钥”和“导入到 CCS”操作入口，替换为一个“快速导入”。
- 禁用、编辑、删除等其他操作保持现有行为。
- 点击后打开快速导入弹窗，绑定当前行密钥；展示名称和脱敏密钥，不默认展示完整密钥。

### 2.2 第一步：选择 Agent

点击快速导入后先展示 Agent 选择页，不直接展示导入方式，也不自动跳过 Agent 选择：

```text
快速导入                                      ×

当前密钥：我的密钥 · sk-****1234
请选择要配置的 Agent

[ Claude Code ]  [ Codex ]  [ OpenCode ]
[ ChatGPT：待明确目标客户端及支持能力 ]
```

每张卡片使用产品正式名称，并附简短说明。ChatGPT 在本方案中是待明确的独立目标，原型中的说明不是必须上线的产品文案；未完成适配时不提供可执行操作。其他已有客户端按现有支持范围补充。

支持配置工具但当前密钥分组不兼容时，可以展示禁用状态及原因；仍允许进入该 Agent 的本工具配置清理入口，避免密钥失效或分组变化后无法恢复。

### 2.3 第二步：选择操作

选择 Agent 后，顶部持续展示已选 Agent，提供“更换 Agent”返回第一步。按以下顺序展示三个选项，其中“一键清理”是第一个选项内部的次级入口，不作为第四张卡片：

```text
快速导入                                      ×

当前密钥：我的密钥 · sk-****1234
当前 Agent：Claude Code          更换 Agent

┌──────────────────────────────────────────┐
│ 一键导入                                 │
│ 自动配置 Claude Code                     │
│                                          │
│ 一键清理                                 │
│ 仅恢复本工具写入的 Claude Code 配置       │
└──────────────────────────────────────────┘

┌──────────────────────────────────────────┐
│ 导入到 CCS                               │
│ 将当前密钥作为 Claude Code 配置导入       │
└──────────────────────────────────────────┘

┌──────────────────────────────────────────┐
│ 手动配置                                 │
│ 查看并复制 Claude Code 配置               │
└──────────────────────────────────────────┘
```

- 点击选项后在同一个弹窗内切换内容，并提供返回操作选择页按钮，避免嵌套弹窗。Agent 选择 → 操作选择 → 对应详情形成一致的返回路径。
- 三种方式均继承已选 Agent，不在子流程内再次选择客户端。不支持某种方式时禁用并说明原因，不能自动改为其他 Agent。
- 已启用管理员设置 `hide_ccs_import_button` 时隐藏 CCS 卡片，快速导入入口及其他选项仍保留。
- 更换 Agent、切换密钥、关闭窗口时清除上一次的临时命令和配置码状态；异步返回结果必须校验当前 Agent 和密钥，防止展示过期结果。
- 缺少分组或密钥不可用时给出具体原因；不签发无法执行的自动配置命令。清理入口不依赖密钥是否仍有效。

### 2.4 创建成功后的衔接

创建密钥成功后展示“密钥创建成功”，提供“快速导入”和“稍后配置”。快速导入打开同一弹窗的 Agent 选择页，绑定刚创建的密钥。

## 3. 一键导入

### 3.1 用户操作

1. 继承第一步已选 Agent，显示其名称与适配说明，校验当前密钥支持该目标，不再次选择客户端。
2. 自动识别操作系统，允许手动切换 Windows、macOS、Linux；WSL 用户选择 Linux。
3. 点击生成配置命令，复制当前平台的一条命令到终端执行。
4. 根据终端结果继续使用客户端；需要重启时明确提示。

页面提供简短的“如何打开终端”帮助。网页无法直接修改本地文件或可靠获知脚本执行结果，因此复制命令不能显示为“导入成功”。最终配置结果以本地脚本输出为准。

### 3.2 脚本能力

Windows 使用 PowerShell `.ps1`；macOS 和 Linux 使用 Shell `.sh` 入口。首轮实现共用 Python 3.11+ 标准库执行器；缺少 Python 或目标客户端时先给出安装说明，安装后重新运行，不静默安装。入口共用配置规则和变更记录格式，通过明确的 Agent 标识分派到各自适配器。Claude Code、Codex、OpenCode 分别管理配置路径、字段、依赖和验证方式；不能用一套文件路径或配置模板套用所有 Agent。

执行过程：

1. 检查系统、客户端、配置路径、写入权限及必要依赖。
2. 检查已有配置、环境变量及可能覆盖配置的设置；遇到无法安全处理的冲突停止并说明。
3. 兑换配置，验证配置版本与目标客户端匹配。
4. 备份受影响内容，记录原始状态。
5. 合并写入 API 地址、密钥、模型等必要字段。
6. 检查配置可解析性和基础连通性；实际模型调用检测作为明确的可选动作，提示可能产生费用。
7. 保存变更记录及本地恢复入口，输出结果、备份位置、下一步操作。

默认只配置当前用户。保留其他供应商、MCP、插件及用户自定义字段。无法解析原配置时停止，不用整份覆盖解决解析错误。写入应采用临时文件和原子替换，并在部分失败时回滚已完成的修改。

客户端未安装时进入明确的安装引导，展示将安装的内容和执行方式；安装成功后继续配置。不得静默申请管理员权限或永久降低系统执行策略。实施时需核实支持版本、官方安装渠道及配置格式，并使用结构化解析方式处理 JSON/TOML，避免文本替换损坏配置。

## 4. 命令与密钥传递

采用“通用脚本 + 短时一次性配置码”，不将长期 API 密钥直接拼接到终端命令。

数据流程：

```text
已登录用户选择密钥和客户端
  → 后端校验密钥归属、状态及目标兼容性
  → 签发短时一次性配置码
  → 页面生成当前平台命令
  → 本地通用脚本通过 HTTPS 兑换配置
  → 配置码失效
  → 本地备份、写入、验证
```

后端要求：

- 配置码建议有效期为 5 分钟，绑定单个密钥、客户端和配置版本，不授予其他账号操作能力。
- 兑换采用原子消费，限制签发及兑换频率；过期、已消费或网络响应丢失后提示重新生成命令，不重复使用原码。
- 兑换时再次校验密钥状态与权限，密钥已删除、禁用或不再兼容时拒绝返回配置。
- 配置码通过请求正文提交，长期密钥不进入下载 URL；相关响应禁止缓存，日志和错误信息脱敏。
- 配置码本身具有临时凭据性质，同样不能记录到业务日志、访问日志或前端分析事件。
- 临时配置使用短时存储；若需要保存完整敏感载荷，应加密并随到期或消费清除。

通用脚本应有明确版本和可审查的发布产物，不包含用户专属密钥。脚本下载和配置兑换仅使用可信 HTTPS 地址。配置及备份在本地限制访问权限，不输出完整密钥。

## 5. 一键清理与恢复

### 5.1 界面与清理范围

“一键清理”位于已选 Agent 的一键导入卡片下方，作为次级入口。点击后继承已选 Agent，只需确认系统并复制清理命令执行。页面和终端均显示“清理并恢复 {Agent} 配置”，不能提供默认清理全部 Agent 的命令。

清理范围仅限本工具自动导入所管理的配置：

- 撤销本工具写入的字段，恢复原有字段值。
- 不卸载客户端，不删除项目、聊天记录，不删除或吊销网站 API 密钥。
- 不清理 CCS 导入或用户手动添加的内容。
- 本地脚本仅列出已选 Agent 的可恢复记录，由用户确认目标后执行；不能仅凭网页当前密钥推断本地当前配置。若目标不一致则拒绝执行，清理 Claude Code 不得触碰 Codex 或 OpenCode 的记录和配置。
- 没有本工具变更记录时明确提示“未找到可清理配置”，不得猜测并删除。

### 5.2 恢复规则

| 本地状态 | 行为 |
| --- | --- |
| 当前字段仍等于本工具写入值 | 恢复原值；原字段不存在则移除 |
| 用户修改了其他字段 | 保留后续修改，仅撤销本工具涉及字段 |
| 用户再次修改了相同字段 | 显示冲突，交由用户选择，不自动覆盖 |
| 本工具新建文件，且内容未被后续修改 | 可删除本工具创建的文件 |
| 本工具新建文件后用户添加了内容 | 保留文件和新增内容，只移除可安全撤销的字段 |

本地记录至少包含操作 ID、脚本版本、客户端、目标路径、原字段存在性及值、写入值、执行状态与时间。包含敏感值的记录和备份必须限制权限。

重复导入不能覆盖最初备份。更换密钥形成独立变更记录，按最近一次操作优先恢复；跨记录存在依赖时先提示，不乱序覆盖。导入和清理需要本地互斥，避免并发修改同一配置。

导入时保存本地恢复脚本和必要依赖，恢复不要求网站在线或密钥有效。网页提供的是便捷清理入口，本地恢复入口应能离线执行。清理后保留必要的结果说明，对含凭据备份提供明确的后续清除方式。

## 6. 导入到 CCS

- 复用现有 `ccswitch://v1/import` 导入机制，以及供应商、地址、密钥、模型和额度查询配置。
- 使用第一步已选 Agent 确定 CCS 导入目标，再校验分组兼容性和 CCS 支持能力；不再根据分组默认值覆盖用户所选 Agent。点击“打开 CC Switch 导入”后唤起应用。
- 提供重试、安装帮助和返回入口。
- 不再使用“100 毫秒后网页仍有焦点”作为未安装的确定证据；页面显示“已尝试打开 CC Switch”，不能声称已完成导入。
- CCS 的确认和导入结果由客户端展示。

首期不承诺 CCS 全自动清理。一键清理只适用于本工具的直接配置脚本。后续若扩展 CCS 自动撤销，需要先核实目标版本公开能力，并可靠记录新增供应商 ID 和原选中供应商；不直接修改其内部数据库。

协议参考：[CC Switch 官方深度链接说明](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/zh/5-faq/5.3-deeplink.md)。具体兼容性在实施时按支持版本验证。

## 7. 手动配置

复用原“使用密钥”的系统切换、认证模式、配置展示、复制和模型目录等能力，入口名称改为“手动配置”。原客户端选择移至弹窗第一步；此处仅展示已选 Agent 的内容，更换目标需返回 Agent 选择页。

将现有内容提取为可嵌入快速导入弹窗的组件，避免在统一弹窗内再打开旧弹窗。现有支持范围不得因新增自动脚本而缩减。

## 8. 实施组织

现有主要接入点：

- `frontend/src/views/user/KeysView.vue`：替换列表操作，接入创建成功引导和统一弹窗。
- `frontend/src/components/keys/UseKeyModal.vue`：复用并提取手动配置内容。
- `frontend/src/utils/ccswitchImport.ts`：复用 CCS 导入逻辑。
- `frontend/src/i18n/locales/zh/dashboard.ts`、`frontend/src/i18n/locales/en/dashboard.ts`：补充快速导入、清理、状态和帮助文案。
- 后端按现有 handler、service、路由组织新增配置码签发和兑换能力，接入现有鉴权、密钥归属校验及限流。

新增统一弹窗、前端配置命令 API 客户端、平台脚本和本地恢复机制。统一维护 Agent 能力描述，包含稳定标识、名称、兼容分组、支持系统、自动导入/清理/CCS/手动配置能力及对应适配器。配置生成规则应统一抽取，使手动配置、自动脚本和 CCS 导入共享目标兼容性、地址与模型映射；各渠道按格式适配，不重复维护业务规则。前端所选 Agent、配置码绑定目标、脚本适配器及本地恢复记录必须使用一致的稳定标识。

实施顺序：

1. 完成 Agent 能力描述、先选 Agent 的统一弹窗和旧能力迁移，保持手动配置及 CCS 行为可用。
2. 完成配置码接口和通用配置描述，确保鉴权与敏感数据处理正确。
3. 完成 Windows/macOS/Linux 的 Claude Code、Codex、OpenCode 独立导入及恢复适配器；ChatGPT 具体目标明确后再评估适配，不以 Codex 实现替代。
4. 接入命令生成、帮助文案和创建成功引导，完成跨平台验证。

自动导入未就绪前不向用户展示可执行但无效的命令；整体达到验收条件后开放。

## 9. 验收要求

### 页面

- 操作列只有“快速导入”，旧的两个独立入口消失。
- 首页先选择 Agent；选定后按顺序展示三个操作选项，一键清理位于一键导入下方。
- 所有操作详情继承所选 Agent，不重复选客户端，不通过分组默认值切换目标；不同 Agent 显示各自配置和支持能力。
- 管理员隐藏 CCS 的设置仍生效，手动配置原有能力可用。
- 创建成功与列表入口使用同一流程；关闭、返回、更换 Agent 和更换密钥不会串用命令、配置码或异步结果。
- 系统可自动识别及手动覆盖；无分组、不支持的客户端、禁用密钥均有清晰反馈。
- 复制命令、唤起 CCS 不会被误报为导入成功。

### 接口与凭据

- 拒绝为其他用户密钥签发配置码。
- 过期、重复兑换、并发兑换、已禁用或删除密钥均按约定处理。
- 日志、URL、错误和分析事件不泄露长期密钥或配置码；敏感响应不缓存。

### 脚本与恢复

- Windows、macOS、Linux 分别验证新建配置、复杂已有配置和含空格/非 ASCII 字符的路径。
- 验证重复导入、更换密钥、客户端未安装、缺依赖、无权限、网络失败和无效配置文件。
- 验证部分写入失败回滚、并发互斥、用户后续修改和恢复冲突处理。
- 验证网站离线或密钥失效时仍可本地恢复。
- 验证清理不删除其他供应商、MCP、用户项目、聊天记录或网站密钥。
- 对每个首期 Agent 分别验证导入和恢复；多个 Agent 共存时，导入或清理其中一个不得修改另一个的配置或备份。

前端执行相关组件测试、类型检查及必要构建；后端覆盖配置码权限、生命周期与并发消费测试；脚本使用隔离用户目录和配置样本测试，并在三个真实目标系统验证。未实际验证的平台应明确标记，不宣称全平台验收通过。

## 模型目录推广补充（2026-09-05）

自动导入的三个目标统一使用 lianjieai 品牌，并在导入时从当前密钥可访问的模型接口同步目录。OpenCode 使用普通 `/v1/models` 数据；Codex 使用带 client_version 的专用目录，保留模型能力与指令元数据；Claude Code 根据版本使用完整模型菜单或所选模型的兼容配置。选择的默认模型必须存在于对应目录。

模型目录与配置一起参与离线恢复。重复导入逐次记录，清理只撤销所选 Agent 最近一次导入；目录或受管配置被后续修改时保留现场并提示冲突。旧版 Claude Code 用户可通过重新导入指定模型切换，完整列表菜单要求 2.1.242 或更新版本。
